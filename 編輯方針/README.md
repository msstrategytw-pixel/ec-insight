# 編輯方針（Editorial Config）

這五份文件是整個情報蒐集 agent 的「大腦設定」。Agent 每次執行時會先讀取它們，再據此決定：去哪裡找資料、什麼算重要、怎麼寫摘要。

**改這些文件 = 調整 agent 的行為，不需要動任何程式碼。**

## 怎麼修改

這個 repo 是唯一來源，三種方式擇一：

1. **直接在 GitHub 網頁改**：點開檔案 → 右上角鉛筆圖示 → 編輯 → Commit changes。適合小修改。
2. **請 AI 幫忙改**：把這個 repo 的連結給 AI（ChatGPT／Claude 皆可，repo 是公開的讀得到），說明你想改什麼，它會產出新版內容，再把結果貼進 GitHub 或交給工程端。
3. **交給工程端**：直接說要改什麼即可。

## 修改守則

1. **用自然語言寫就好**。這些文件是給 AI 讀的，寫得像在跟一個新進同事交接即可，不需要任何特殊格式。
2. **改範例比改定義有效**。覺得 agent 選材不準時，優先去[評分標準.md](評分標準.md)的範例庫加一筆「這篇不該選（原因）」或「這種要多選（原因）」，比修改抽象定義見效快。
3. **保留既有結構**（標題層級、表格、修改紀錄），agent 依賴這些結構定位資訊。
4. 每次修改請在文件最下方的「修改紀錄」加一行：日期、誰、改了什麼。之後對照「有用率」變化時，才知道是哪次修改造成的。
5. **大改可以先試跑**：改完後可以要求 agent「用新方針重跑上一期，對照哪些會被刷掉、哪些會新增」，確認方向再等下次正式執行。

## 注意

- 調整產業或其啟用狀態時，需同步更新 `docs/data/industries.json`（網站的產業選項以該檔為準），兩邊名稱必須完全一致。
- 修改後於下次執行時生效，不需通知任何人。
